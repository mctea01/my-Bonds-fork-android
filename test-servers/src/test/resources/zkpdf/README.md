# Synthetic zkPDF fixtures

Generated by the code and instructions in `tools/zkpdf-testdocs/`. All document
content is fictional. Signed by the deterministic DIW SYNTHETIC DS test key,
chained to `test-root.cer`; never an official or production signer.

| File | Purpose |
| --- | --- |
| `student.pdf` | One-page unencrypted student-status layout, WinAnsi digits, Type0 Chinese and QR image. Positive input for Z1. |
| `travel-rc4.pdf` | One-page travel-record layout, Standard V2/R3 RC4-128, empty user password and CID digits. Positive RC4 input and Z10 mutation source. |
| `student-inline-image.pdf` | Signed content includes an inline `BI` image; Z8 rejection input. |
| `student-actual-text.pdf` | Signed content includes an `/ActualText` marked-content property; Z8 rejection input. |
| `student-oversized.pdf` | Signed content decompresses past `MAX_PLAIN=40960`; Z12 rejection input. |
| `student-modified.pdf` | Incremental update after signing changes the first-page content; Z11 input. |
| `test-root.cer` | Public DER certificate for the synthetic test root. |

The negative PDFs have valid signatures over their signed revisions. Their
rejection conditions are structural or scope restrictions, not corrupt CMS
signatures. Normal tests compare every committed binary with regenerated bytes.
