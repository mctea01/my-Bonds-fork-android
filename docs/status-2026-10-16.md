## 範圍與原則

這是個人使用的 Android／Windows／Linux 數位身分錢包。**依公開規格完成行動自然人憑證、CSC 遠端簽章與電子公文檔案的協定、驗證、簽署與封裝流程，即符合本階段目標**。正式介接機關公文交換中心、內政部 SP 或商業 QTSP，需要個別的機關或服務商核准，對個人錢包不是預期的預設能力，也**不是程式未完成的判定標準**。相關介面不可捏造、不可用測試 PKI 冒充正式身分。

本頁以四種狀態區分：
- **已實作**：可在現有原始碼找到完整主流程；不代表實機成功。
- **自動測試通過／待複驗**：以指定 commit 的 GitHub Actions／模擬測試為準。
- **未實作／部分支援**：有明確的協定路徑或功能仍缺少。
- **外部授權不適用**：公開規格已具備，但個人無法取得服務商／機關註冊。不是阻擋合併的缺陷。

## PR #11 本輪修補重點

1. **OpenID4VCI**：用授權伺服器的 `token_endpoint_auth_methods_supported` 協商 Client Authentication；已選擇的方法貫穿 PAR／Token；後端支援短效錢包實例 PoP 與測試受信任的 Client Assertion。
2. **OpenID4VP**：DC API 簽章協定識別嚴格核對；多重簽章採 JSON Serialization，逐一驗證查驗方簽章、Client ID 與信任等級，不轉成未簽章要求。
3. **CSC**：授權回呼綁定登記的 `redirect_uri`，檢查 OAuth／Token 的 HTTPS 與 Bearer Token，簽章演算法不從 SHA-256 降級到未知演算法。
4. **TW FidO**：加入 SP checksum／Ticket 解析回歸測試、正常傳遞取消訊號。
5. **正式／測試隔離**：正式 HTTPS Wallet Provider 可以設定；本地測試簽章僅由對應測試環境信任。

## 驗收門檻與 CI

- 原 PR #11 commit `42274f7755df4e4cce48019d41ea8485ce4066f7` 曾通過 GitHub CI；**後續修改必須重新以最新 commit 驗證，不沿用舊綠燈。**
- 核心與 App：`./gradlew :core:compileKotlinJvm :app:compileKotlinDesktop :test-servers:test :app:desktopTest :app:assembleRelease`。
- CI：Android Release 必須經 R8、Linux／Windows Desktop、協定／UI 測試及測試報告通過；取消或排隊不等於通過。
- 實機：Android Keystore／使用者驗證、DC API、NFC／BLE、公開發證端與查驗端、Mobile MOICA UAT（僅限持有 SP 資格時）與 CSC 測試服務（僅限可用帳號時）。
- 發證端與查驗端信任分開；**T3 的提示不等同 Token Request 的 `clientId must be authenticated` 錯誤。**
