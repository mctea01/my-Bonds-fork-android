# P1 到 P3 補強：用戶端驗證、出示與 mdoc 簽署清單（2026-10-16）

分支 `claude/openid4vci-client-auth-20261016`，以 main（P3 合併後）為基礎。這一輪補強 P1 到 P3 已有的協議路徑，不屬於 P4。

## 修正與新增

1. **OpenID4VCI 用戶端驗證協商（`Oid4vciClient.clientAuthenticationFor`）。**
   - 依發證端 `token_endpoint_auth_methods_supported` 依序選擇：`attest_jwt_client_auth`（錢包後端發 Wallet Attestation）、`private_key_jwt`（錢包後端的 `client-assertion` 端點簽 RFC 7523 assertion，請求以錢包實例金鑰的 proof 綁定）、公開用戶端。
   - 公開用戶端在發證端沒有列出 `none` 時也會嘗試，因為 Keycloak 與 EUDI 發證端接受公開用戶端加 PKCE 卻不列出 `none`；PAR 或 Token 回 `invalid_client` 時改報 `client_authentication_unavailable` 並列出發證端要求的方式。
   - 錢包後端回 404 視為不支援該方式，改試下一種；沒有到期時間的 Wallet Attestation 不再重複使用；錢包送給後端的 Client Assertion 請求 proof 有效 5 分鐘，測試後端拒絕已過期或效期超過 10 分鐘的 proof。
   - 錢包後端在「設定 > 互通 > OpenID4VCI 錢包身分」設定，只接受 HTTPS；快取依後端網址、`client_id` 與是否為本機測試後端區分。
   - 測試：`Oid4vciE2eTest` 的 `clientAssertionPreAuthorized`、`clientAssertionWithParAndPkce`、`clientAssertionIsUsedWhenAttestationNotAvailable`、`clientAssertionRequiredRejectsPublicClient`、`publicClientIsTriedWhenMetadataOmitsNone`。
2. **DC API `openid4vp-v1-multisigned`（JWS JSON Serialization）。**
   - 每個簽章的 protected header 各自帶 `client_id`，逐一驗證；採用驗證成功且信任等級最高的簽章（`TrustTier` 數值較小者）。
   - 偽造簽章、`expected_origins` 與呼叫來源不符、以未簽章協議冒充已簽章請求都拒絕。
   - 測試：`Oid4vpE2eTest` 的 `dcApiMultiSignedChoosesAnAuthenticatedVerifier`、`dcApiMultiSignedRejectsForgedSignaturesAndOrigins`、`dcApiSignedProtocolCannotDowngradeToUnsigned`。
3. **加密的要求物件（JWE，ECDH-ES）。**
   - 只用錢包自己登記的解密金鑰；加密不代表查驗方身分，未簽章的內層物件仍視為未驗證。
   - 只加密不簽章時，內層 `client_id` 必須等於外層；已簽章的物件交給一般驗證（舊版物件可能沒有 `client_id`）。
   - Multipaz `JsonWebEncryption.decrypt` 一律以長度前綴處理 apu／apv，加密端未帶 apu／apv 時解不開（`AEADBadTagException`）。
   - 測試：`EncryptedRequestObjectTest` 的 `decryptsOnlyWithWalletControlledKeyAndKeepsIdentityUnauthenticated`、`aSignedClientCannotUseEncryptionInsteadOfVerifierAuthentication`。
4. **mdoc transaction_data。**
   - 以 Multipaz `TransactionType` 產生 DeviceSigned 資料，元素必須在 MSO KeyAuthorizations 允許的命名空間或元素內；不適用、沒有產生資料或互相衝突時拒絕。零知識 mdoc 不支援 transaction_data。
   - 測試：`Oid4vpE2eTest` 的 `mdocTransactionDataIsBoundToAuthorizedDeviceNamespace`、`mdocTransactionWithoutIssuerKeyAuthorizationIsRejected`。
5. **mdoc 簽署清單（VICAL、RICAL）。**
   - 簽署者必須連到 `TrustRole.TRUST_LIST_PROVIDER` 的錨點，且與清單在同一個環境，測試根憑證簽的清單不會進入正式環境；RICAL 項目必須標為信任錨點。
   - 每個角色與環境另有保存來源的 TrustManager（`signed-lists-<角色>-<環境>`），檢查版本倒退與發行者；目前生效的 TrustManager 只放未過期的清單。過期（現在時間不早於 `notAfter`）的清單停止提供信任，但來源保留，可更新或移除。
   - 開啟 App 時與按「更新到期的清單」時，下載下次更新時間已到、沒有下次更新時間或已過期的清單；一份失敗不影響其他清單，失敗原因一併回報。
   - 介面在「設定 > 信任 > 自訂信任」的「mdoc 簽署清單」（AGENTS 規則 12），使用者匯入的清單為 T2（規則 3，`TrustViews` 已更新說明）。
   - 測試：`SignedMdocTrustListsTest` 的 `verifiedListsRequireIndependentPublisherTrust`、`refusesRollbackAndExpiredLists`、`ricalOnlyAuthorizesVerifierCertificates`、`expiredListStopsTrustButCanBeRefreshedAndRemoved`、`oneFailingListDoesNotStopTheRefresh`。
6. **CSC 遠端簽章。** OAuth 授權與 Token 端點必須是 HTTPS（測試服務的本機位址除外）；回呼網址必須等於登記的 `redirect_uri`；只接受 Bearer 權杖；憑證沒有宣告 SHA-256 的 ECDSA 或 RSA 演算法時不簽。測試：`CscSigningTest` 的 `insecureOAuthEndpointsAreRejected`、`wrongOAuthCallbackUriIsRejected`。
7. **行動自然人憑證。** 網路呼叫中的取消不再被當成一般錯誤；checksum 涵蓋整個回應、缺少識別碼的 ticket 拒絕。測試：`MobileMoicaTest` 的 `checksumAuthenticatesTheEntireResponse`、`ticketParsingRejectsMissingIdentifiers`。

## 與原則的對照

| 規則 | 處理 |
|---|---|
| 1 標準優先，方言隔離 | 以上都在標準路徑（OpenID4VCI、OpenID4VP、ISO 18013-5、CSC），沒有方言邏輯 |
| 3 信任分層 | 使用者匯入的 mdoc 簽署清單為 T2，測試清單不升為正式；`TrustViews` 說明已更新 |
| 10 設定分組 | 錢包身分在「互通」，清單在「信任」 |
| 12 自訂信任集中 | VICAL、RICAL 從信任頁移到 `Screen.CustomTrust` |
