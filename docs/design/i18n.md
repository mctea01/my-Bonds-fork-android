# 多語系（i18n）規劃

性質：規格。2026-11-05 規劃；I1、I2、I3 於 2026-11-06 實作並合併進 main（PR #89，做法見第 6 節），之後新增的文字都照這裡的規則。目前狀態見 [專案現況](../STATUS.md)。

## 1. 實作前的狀況（2026-11-05）

- 介面文字幾乎都寫死在 Kotlin 原始碼：`app` 的 commonMain 約 3,270 個含中文的字串常值（45 個檔案，`FilesScreens.kt` 639 個最多，其次 `FilesModel.kt`、`CredentialDetails.kt`、`SettingsScreen.kt`、`TrustAnchorsScreen.kt`），androidMain 約 100 個；`core` 的 commonMain 約 2,050 個、jvmCommonMain 約 500 個，多數是判定理由、解析結果的欄位名稱與錯誤訊息，會直接顯示給使用者。
- Android 的 `res/values/strings.xml` 只有 App 名稱與 NFC 服務名稱。
- 已有的語系處理：`WalletModel.locales`（使用者語言清單，最後補英文）與 `ClaimLabels`（依語言選發證端提供的欄位名稱，沒有時用快取的常用關鍵字翻譯）。這部分維持不變。
- 尚未使用 Compose Multiplatform 的資源函式庫（`compose.components.resources`）。

## 2. 決定

| 項目 | 建議 |
|---|---|
| 語言 | 第一階段繁體中文與英文；之後視需要加簡體中文（大陸文件使用者） |
| 機制 | Compose Multiplatform resources：`app/src/commonMain/composeResources/values*/strings.xml`，畫面以 `stringResource(Res.string.x)` 取用，Android 與桌面版共用 |
| 預設語言 | `values/` 放英文，`values-zh/` 放繁體中文。裝置是中文（台灣、香港、中國）時都顯示繁體中文，直到有 `values-zh-rCN`；其他語言的裝置顯示英文 |
| App 內切換語言 | 設定 > 顯示加「語言」：跟隨系統、繁體中文、English。Android 13 以上用系統的每個 App 語言設定（`android:localeConfig`），桌面版存在設定並在啟動時套用 |
| AAB 語言分割 | `android { bundle { language { enableSplit = false } } }`，否則從 Play 安裝時只會帶裝置語言的 `res/values-*`，App 內切換後 Android 資源（App 名稱、NFC 服務名稱）缺字；composeResources 在 assets 內，本來就不分割 |
| core 的訊息 | core 不依賴 Compose。使用者看得到的訊息改成「訊息代碼加參數」（例如 `Msg(TRUST_CHAIN_UNTRUSTED, mapOf("subject" to cn))`），由 app 對應到字串資源；尚未對應的代碼顯示原本的中文，逐步搬移 |
| 開發者訊息 | 例外與 log 用英文，不翻譯 |
| 規格原文 | 憑證狀態等依規格原文顯示的值（例如 `revoked`）不翻譯，旁邊可加翻譯說明（沿用既有決定） |
| 日期與數字 | 依目前語言格式化（kotlinx-datetime 加平台格式器），不再寫死「年月日」格式 |
| 複數 | 英文需要的單複數用 `<plurals>` |

## 4. 工作拆分

| 階段 | 內容 | 驗收 |
|---|---|---|
| I1 基礎 | 加入 resources 函式庫、`values` 與 `values-zh`、語言設定、`localeConfig`、AAB 不分割語言；搬移導覽列、設定、首次啟動與法律聲明頁 | 兩種語言切換後畫面即時更新；desktopTest 以兩種語言繪製截圖 |
| I2 App 畫面 | 依檔案逐一搬移 app 的字串（先 `HomeTabs`、`FlowScreens`、`SettingsScreen`，最後 `FilesScreens`） | app 的 UI 檔案沒有中文常值（檢查腳本） |
| I3 core 訊息 | 判定理由、解析結果欄位名稱、錯誤訊息改成代碼加參數 | 主要流程（領卡、出示、文件驗證、簽署）在英文下沒有中文 |
| I4 上架素材 | 英文商店資訊定稿（[google-play.md](../google-play.md) 已有草稿）、英文截圖 | Play Console 的 en-US 商店資訊完整 |

搬移是機械性工作量大、風險低的改動，適合分批交給 Codex（每批只動列出的檔案，介面與命名規則由本文件規定），每批合併前跑 `:app:desktopTest` 與截圖比對。

## 5. 檢查

- 以腳本列出 UI 檔案中的中文常值，加入 CI 只警告、I2 完成後改為失敗；允許清單只放規格原文與測試資料。
- 偽語系（例如把英文字串加長 40%）檢查版面截斷。
- 中文檔名與文件內容不受語系影響（2026-10-16 的要求：全程不能出現 `?` 或亂碼），測試要在英文介面下匯入中文檔名的文件。

## 6. 實作現況與做法（2026-11-06）

I1 已完成：

- `compose.components.resources`，產生的類別在 `diw.wallet.app.res`（`Res.string.*`）。字串檔 `app/src/commonMain/composeResources/values/strings.xml`（英文）與 `values-zh/strings.xml`（繁體中文），兩邊的鍵必須相同，`LocalizationTest` 檢查鍵、佔位符（`%1$s`）與英文檔沒有中文。
- 語言選擇：`AppLanguage`（跟隨系統、繁體中文、English）存在 `AppLanguageStore`。Android 13 以上是系統的每個 App 語言（`LocaleManager`，`res/xml/locales_config.xml`，系統設定也能改），較舊的 Android 存在 SharedPreferences，桌面版存在 Java Preferences（解鎖前就套用）。`AppLocaleScope` 依選擇覆寫畫面的語系並重繪（Android 13 以上交給系統，不覆寫）。設定 > 顯示與語言、首次啟動的歡迎頁都可切換。
- 畫面外的字串（訊息、協程）用 `WalletModel.text(Res.string.x, args)`（或 `AppLanguageStore.text`），它依 App 的語言建立資源環境；不要用沒有環境參數的 `getString`，它只看系統語言（Android 會忽略 App 語言），桌面測試沒有顯示器時還會失敗。
- 同步的模型程式（訊息、歷史紀錄、enum 的顯示名稱）用 `tr(Res.string.x, args)`：`AppText` 在 `WalletModel.init` 一開始依 App 語言把全部字串載入記憶體，語言變更時重新載入。需要文字的 enum 存 `StringResource`（`private val titleRes`），以 getter `val title: String get() = tr(titleRes)` 提供；原本的 `const val` 改成 `val X: String get() = tr(...)`。
- 保留中文的常值：用來比對或解析文件內容的文字（MyData 檔名關鍵字表與檔名格式、核心備註比對、「年度」後綴、`等級：`、`ENCRYPTED_PDF_PROBLEM`）必須維持中文，否則會認不出中文文件。
- 歷史紀錄與檔案來源文字以記錄當時的語言保存，切換語言不會改寫舊紀錄。
- `desktopTest` 以 `-Duser.language=zh -Duser.country=TW` 執行，既有斷言中文的測試仍成立；`LocalizationTest.modelStringsFollowTheLoadedLanguage` 檢查 `tr` 跟隨載入的語言。
- Android 資源：`values`（英文）與 `values-zh` 的 NFC 服務名稱；AAB 關閉語言分割。
- 已搬移：導覽列與各畫面標題、證件內容頁、設定（全部 9 頁）、首次啟動與法律設定的介面、桌面版解鎖畫面。法律文件本文（2026-11-06 使用者決定翻譯）：繁體中文原文在 `LegalTextsZh`（`LegalTexts.kt`），英文譯本在 `LegalTextsEn.kt`，`LegalTexts` 依介面語言（資源 `legal_language`）選用；兩種語言共用 id 與 version，同意紀錄不因語言不同而重問。英文譯本開頭註明以中文原文為準（`legal_translation_note`）。網頁版：中文在 `docs/legal/`，英文在 `docs/legal/en/`；`LegalDocumentsTest` 檢查兩者與程式一致、譯本與原文的節數與條列數相同、英文無中文字。修改法律文字時兩種語言都要改。
- 截圖：`DIW_SCREENSHOTS=<資料夾> ./gradlew :app:desktopTest --tests '*legalScreenshots'` 以兩種語言繪製首次啟動、法律與設定頁（`legal-*`、`legal-en-*`）。

搬移工具 `tools/i18n/i18n.py`：

1. `python3 tools/i18n/i18n.py extract <檔案>` 列出含中文的字串常值（序號、行號、以 `%n$s` 表示的範本、參數運算式）。
2. 寫翻譯檔（UTF-8，每行「序號<TAB>鍵<TAB>英文」），鍵以畫面分組（例如 `settings_*`、`screen_*`），通用文字共用（`action_cancel`、`state_on`）。同一個鍵只能對應同一段中文。不在 composition 內的常值（例如 enum 參數）寫成 `@鍵`，工具會放入 `Res.string.鍵`。
3. `python3 tools/i18n/i18n.py apply <檔案> <翻譯檔> [--tr]` 取代常值並寫入兩個字串檔；加 `--tr` 時產生 `tr(...)`（模型程式）。之後編譯，依錯誤把非 `@Composable` 的函式加上 `@Composable`，或在 lambda 外先取值；協程內改用 `model.text`。
4. `python3 tools/i18n/i18n.py check <檔案...>` 統計剩下的中文常值。

注意事項：字串前後的空白會保留（片段串接用）；以「、」「，」分隔的清單用 `sep_list`、`sep_comma`；英文的元件名稱不用翻譯成中文分隔號。

I3 core 訊息（2026-11-06）：

- core 不依賴 Compose 資源。使用者看得到的訊息改成 `ct("core_鍵", 參數)`（`diw.wallet.core.i18n`），`CoreText.resolver` 由 App 的 `AppText` 設定，依 App 語言從字串資源取文字；沒有 App 時（core 單獨使用、伺服器）用 `CoreStrings.ZH` 的繁體中文。`CoreStrings.kt` 由工具從 `values-zh` 的 `core_` 鍵產生，`LocalizationTest.coreMessagesHaveBothLanguages` 檢查兩邊一致。
- 搬移：`python3 tools/i18n/i18n.py apply <core 檔案> <翻譯檔> --core`，鍵自動加 `core_` 前綴。enum 的顯示名稱存鍵（`private val titleKey`）並以 getter 取文字；`const val` 與物件層級的 `val` 改成 getter，否則語言在初始化時就固定。
- 訊息之間的比對不再用中文片段：同一則訊息比對 `ct(鍵)`，有參數的比對 `CoreText.prefix(鍵)`；App 判斷公文、線上簽核與加密 PDF 時同時比對目前語言與 `CoreText.chinese(鍵)`（舊報告）；簽章等級以 `B-B` 至 `B-LTA` 的格式辨識。
- 刻意保留中文：衍生憑證的欄位名稱與內容（`DocumentFields`、`BondsHolderDerived`、`BondsNationalId`、`StudentStatusProof`、大陸出入境等，憑證內容依文件語言）、信任錨點名稱（`BuiltInPublicRoots`、`BuiltInAnchors`、`BuiltInTestAnchors`）、解析公文與戶籍謄本用的元素名稱與關鍵字（`OfficialDocuments`、`ExchangeFiles`、`OfficialBundles`、`ApprovalPoint`、`HouseholdTranscript`、`ClaimSensitivity`）、`ClaimLabels` 的中文欄位表（依語系選用），以及送給 Bonds App 的年齡查驗結果文字（`BondsAgeVerification`）。
- 檢查結果與歷史紀錄以產生當時的語言保存；切換語言後重新檢查文件即可得到新語言的報告。

剩餘量（2026-11-06，`check`）：app 只剩 `LegalTextsZh`（法律原文）與上述刻意保留的比對用中文；core 約 1,550 個，都是上面列出的資料與比對用文字。
