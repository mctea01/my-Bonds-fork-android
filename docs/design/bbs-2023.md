# bbs-2023（W3C Data Integrity BBS Cryptosuites）

現況（2026-11-12）：錢包、測試發證端與查驗端都支援 bbs-2023，包括基本選擇性揭露與三種可選功能（匿名持有者綁定、假名、持有者綁定假名）。

## 1. 規格與版本

- W3C Data Integrity BBS Cryptosuites v1.0（CRD 2026-09-10），cryptosuite 名稱為 `bbs-2023`。
- 共用的選擇性揭露函式（skolemize、標籤對照、selectJsonLd、canonicalizeAndGroup）來自 Data Integrity 1.1。RDF 正規化使用 RDFC-1.0。
- BBS 原語來自 IRTF CFRG：
  - 簽章：`draft-irtf-cfrg-bbs-signatures`。
  - 盲簽：`draft-irtf-cfrg-bbs-blind-signatures-02`。
  - 假名：`draft-irtf-cfrg-bbs-per-verifier-linkability-03`。
  - 這些都由 zkryptium 0.8.1 實作（`native/vendor/zkryptium`，只保留 BBS 部分並依 W3C 測試向量修補）。
- 金鑰為 BLS12-381 G2 Multikey（multicodec 0xeb，varint `eb 01`，`did:key:zUC7...`）。

| 位置 | 內容 |

## 3. 測試向量與規格差異

`test-servers/src/test/resources/bbs-2023/` 收錄 W3C 附錄 A 的測試向量，由 `Bbs2023Test` 逐位元組比對：

- 基礎 proofValue。
- 衍生揭露資料。
- 匿名持有者綁定。
- 假名。

向量與規格本文不一致的地方如下：

- 假名向量的標頭用 0x08 與 0x09，連一般 pseudonym 也一樣。
- `signer_nym_entropy` 以 CBOR tag 2（bignum）編碼。
- 衍生假名 proof 只有 7 個元素，沒有 nym_domain。
- `prCredUnsigned.json` 不是實際簽署的文件。

本實作寫出時依規格本文，衍生假名 proof 有 8 個元素並以文字帶 nym_domain。讀取時兩種形式都接受。

Digital Bazaar 的 JavaScript 實作（`@digitalbazaar/bbs-2023-cryptosuite` 2.0.1，最後更新 2024-08）只支援基本版（標頭 0x02 與 0x03），不支援可選功能。它測試用的 windsurf 基礎與衍生 proofValue 和我們收錄的 W3C 向量逐位元組相同，所以基本版兩邊互通。它的讀取器接受以 CBOR tag 64（RFC 8746 uint8 typed array）包裝的位元組字串，我們的讀取器也接受。

功能標頭由出示者寫入，不能直接信任。查驗時以 BBS 證明隱藏的訊息數決定實際功能：

| 功能 | 簽署者訊息以外隱藏的訊息數 | 內容 |
| --- | --- | --- |
| 基本版 | 0 | 無 |
| 匿名持有者綁定 | 2 | holder secret、secret_prover_blind |
| 假名 | 2 | secret_prover_blind、nym_secret |
| 持有者綁定假名 | 3 | 以上三者 |

數量不符就拒絕。唯一的例外是標頭 0x09 但只隱藏 2 個訊息（測試向量的寫法），這種情況視為一般假名，不算持有者綁定。

JSON-LD 處理採安全模式（Titanium 的 `undefinedTermsPolicy = Fail`）：context 沒有定義、或被 context 對應為 null 的成員一律報錯。原因是這類成員不在簽署的 RDF 裡，查驗方卻會從 JSON 讀到。

## 4. DIW 約定（BbsProfile）

規格沒有規定 OpenID4VCI 如何傳遞持有者承諾，也沒有規定 OpenID4VP 的 presentation header 與 nym_domain，因此本專案自訂約定如下。

### 發證（DIW 擴充）

- 發證端在 credential configuration 以 `diw_bbs_features` 列出提供的可選功能。
- 錢包依以下順序選擇一項：
  1. `anonymous_holder_binding`
  2. `holder_binding_pseudonym`
  3. `pseudonym`
- 錢包在 credential request 加入 `diw_bbs_commitment`：`{"feature": ..., "commitment_with_proof": base64url}`，一次只申請一張。
- 沒有列出可選功能的發證端收到的是一般請求，發出基本版憑證。
- 持有者秘密存在 `W3cVcCredential`（CBOR `bbsSecrets`）：
  - `secret_prover_blind`
  - holder secret
  - prover_nym
  - 收卡驗證時算出的 nym_secret

  這些秘密只留在本機，不會送出。

### 出示

每次出示都由原始憑證即時衍生：

- 揭露請求的欄位加上發證端的必揭露指標。
- 綁定 DID 的憑證另外揭露 `credentialSubject.id`。
- 同意畫面在請求的欄位之外，也列出發證端必揭露指標底下的所有欄位，以及要送出的 `credentialSubject.id`；敏感度依完整的揭露集合計算。
- presentation header 為 JCS 的 `{"aud": audience, "nonce": nonce}`。
- 假名的 nym_domain 為 audience：client_id，DC API 則為 `origin:<origin>`。因此同一查驗端每次看到相同假名，不同查驗端之間無法連結。

衍生出的憑證放進 vp_token 的方式：

| 憑證 | 放法 |
| --- | --- |
| 綁定 DID 的憑證 | 照舊放進持有者簽的 ldp_vp（challenge 為 nonce、domain 為 audience） |
| 匿名持有者綁定或假名憑證（沒有 DID） | 直接放衍生後的 VC，由 BBS 證明本身證明持有者，presentation header 保證新鮮 |

DCQL 的 `require_cryptographic_holder_binding`：

- 值為 true 時，可以由匿名持有者綁定或持有者綁定假名的憑證回應。
- 一般假名憑證只能回應不要求綁定的請求。

### 查驗端

`PresentationVerifier` 處理 DCQL 中的 ldp_vc 與 ldp_vp 查詢，依序檢查：

1. VP 的 proof：authentication、challenge、domain，以及簽署者必須是 holder。
2. VC 的 proof：assertionMethod，簽署者必須是 issuer DID。
3. bbs-2023 的 presentation header 必須等於本次請求的值。基礎 proof 不能當作出示。
4. 持有者綁定：二選一。
   - VP holder 等於 credentialSubject.id。
   - 持有者綁定功能的衍生 proof。
5. 假名必須為本查驗端產生。
6. type、請求欄位與有效期間。
7. 以 `DidTrust` 判定發證端 DID。

假名以 base64url 列在結果的 `pseudonym` 欄位。

## 5. 測試伺服器

`IssuerService` 有四個 ldp_vc 設定，都使用 bbs-2023 簽發虛構資料：

| 設定 | 內容 |
| --- | --- |
| `w3c_ldp_vc` | 綁定 did:key，jwt proof |
| `w3c_ldp_vc_private` | 三種可選功能都提供，錢包會選匿名持有者綁定 |
| `w3c_ldp_vc_pseudonym` | 只提供持有者綁定假名 |
| `w3c_ldp_vc_nym` | 只提供假名 |

- 必揭露指標為 `/issuer`、`/validFrom`、`/validUntil`。
- 測試查驗端把發證端的 BBS DID 視為 TEST 環境的發證端。
- `Bbs2023E2eTest` 涵蓋發證、出示與查驗的端對端流程，包括：
  - 只揭露請求欄位。
  - 匿名持有者綁定不送識別碼。
  - 假名對同一查驗端穩定、對不同查驗端不同。
  - 不要求綁定的假名出示。

## 6. 依賴與發佈

- JSON-LD 處理使用 Titanium JSON-LD 1.7.0（Apache-2.0）與 Glassfish Jakarta JSON 2.0.1（EPL-2.0），都是 Java 程式庫，不含原生碼。
- Titanium 內建的 OkHttp 載入器已排除，context 一律經 `LdContextLoader` 載入：先查內建清單，再以 HTTPS 下載，大小上限 1 MiB。
- R8 與 ProGuard 保留 `org.glassfish.json.JsonProviderImpl`（`app/proguard-rules.pro`、`app/compose-desktop.pro`）。
- 沒有原生庫的組建（例如 `-Pdiw.zkNative=skip`）仍可編譯：bbs-2023 憑證查驗會回報不支援，錢包不會選擇可選功能。
